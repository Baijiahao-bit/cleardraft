# 净稿 · ClearDraft 使用方法

## 先确定目标

本工具适合检查并清理指定不可见字符、部分元数据，或把可抽取的文字重新排版成新文档。它不能给出“没有 GPT 隐形水印”的证明；原样重打文字也不会构成统计选词水印的去除方法。原理和依据见 [技术原理与官方依据](技术原理与官方依据.md)。

处理重要文档时，请始终保留原件，并在输出后核对内容。工具拒绝覆盖原件和已有输出文件。

## Windows 安装与图形界面

1. 安装 Python 3.11 或更高版本。使用 Python 官方 Windows 安装程序时勾选 **Add python.exe to PATH**，并保留 Tcl/Tk 组件，以便使用图形界面。
2. 把整个项目文件夹放到本地，双击 `安装.cmd`。首次安装需要联网下载 Python 依赖。
3. 安装完成后双击 `启动.cmd`。
4. 选择输入文件，查看检查结果，再选择输出文件路径。
5. 默认使用“保版清理”（保留模式）。如果希望重新输入式导出或转换格式，选择“文字重建”（重建模式），阅读复杂内容提示。
6. 处理后打开新文件，检查文本、表格、图片、公式和分页，再查看 JSON 审计报告。

如果窗口未启动，在项目目录打开 PowerShell，执行下面的命令，保留终端中的错误信息用于排查：

```powershell
python --version
python -m pip install -r requirements.txt
python -m cleanroom --help
python -m cleanroom gui
```

`安装.cmd` 和 `启动.cmd` 面向 Windows。其他系统可以使用命令行；图形界面需要系统提供 Tkinter。

## 命令行操作

所有命令均在项目根目录执行。文件路径包含中文、空格时请使用双引号。下面的文件名为示例，运行前替换为自己的实际路径。输入文件上限为 100 MiB；输出文件夹必须已存在，保留模式的输入输出扩展名必须相同。

### 只检查，不修改

```powershell
python -m cleanroom inspect "D:\我的文档\原稿.docx"
python -m cleanroom inspect "D:\我的文档\原稿.pdf"
```

检查结果以 JSON 输出。检查是针对本工具支持的字符、文本和文档结构项目，不是 textGrain 官方检测，也不是 AI 写作概率评分。

### Word 保留模式

```powershell
python -m cleanroom clean "D:\我的文档\原稿.docx" -o "D:\我的文档\清理版.docx" --mode preserve
```

保留模式尽量保留原有 DOCX 结构，处理支持的文本节点、文档属性和编辑会话标识。复杂部件中的候选信息可能保留；请查看检查结果。它不保证删除嵌入对象中的全部信息。

### PDF 保留模式

```powershell
python -m cleanroom clean "D:\我的文档\原稿.pdf" -o "D:\我的文档\清理版.pdf" --mode preserve
```

PDF 保留模式只清理支持的元数据，不修改页面文字，因此不会删除页面文本里的不可见字符。若需要处理可抽取文字中的指定字符，使用重建模式。

### 重建或转换格式

```powershell
python -m cleanroom clean "原稿.docx" -o "重建版.docx" --mode rebuild
python -m cleanroom clean "原稿.pdf" -o "重建版.docx" --mode rebuild
python -m cleanroom clean "原稿.docx" -o "重建版.pdf" --mode rebuild
python -m cleanroom clean "原稿.txt" -o "重建版.pdf" --mode rebuild
```

重建模式先抽取文字，再创建新文件。PDF 的阅读顺序取决于原始文本层，双栏、表格或复杂排版可能导致抽取顺序不理想。新文件会重新排版，不承诺原有字体、字号、分页或页数。

检测到可能丢失的复杂内容时，默认拒绝继续。仅在确认接受相应损失后使用：

```powershell
python -m cleanroom clean "含图片和公式的原稿.docx" -o "仅文字重建版.docx" --mode rebuild --allow-lossy
```

图片、公式、批注、页眉页脚等内容可能丢失。该选项表示接受有损重建，不表示这些内容已被识别或保留下来。扫描件不支持 OCR；没有可抽取文字的扫描页仍然无法重建。

### 保留不可见字符

```powershell
python -m cleanroom clean "原稿.docx" -o "仅清理属性版.docx" --keep-invisibles
```

此选项保留清理名单中的四种字符。它不关闭所有文档属性处理，也不改变输出文件需要使用新路径的规则。

### 纯文本和 Markdown

```powershell
python -m cleanroom clean "原稿.txt" -o "清理版.txt"
python -m cleanroom clean "原稿.md" -o "清理版.md"
```

文本文件按 UTF-8 读取；其他编码请先转换为 UTF-8。Markdown 作为文本处理，不等同于浏览器渲染后的富文档。转换为 PDF 或 DOCX 时不要假设 Markdown 表格、公式和图片链接会变为对应排版对象。

## 参数速查

| 参数 | 含义 |
| --- | --- |
| `inspect INPUT` | 检查文件并输出 JSON |
| `gui` | 启动本地图形界面 |
| `clean INPUT -o OUTPUT` | 处理文件，生成新文件及审计报告 |
| `--mode preserve` | 默认模式，保留受支持格式的文档结构 |
| `--mode rebuild` | 抽取文字并重新排版，支持跨格式输出 |
| `--keep-invisibles` | 保留指定的四种不可见字符 |
| `--allow-lossy` | 明确接受检测到的复杂内容在重建中丢失 |
| `--help` | 显示命令帮助，以当前版本帮助为准 |

## 查看结果与报告

审计报告位于输出文件旁边，文件名是在完整输出文件名后追加 `.audit.json`。例如 `清理版.docx` 对应 `清理版.docx.audit.json`。报告应与同次处理的输出一起保存，以便把输入、输出、处理参数和检查结论对应起来。

重点查看以下内容：

- 处理模式是否符合预期，是否启用了有损重建。
- 清理名单内的字符和支持的文档属性是否有残留。
- 忽略空白的正文一致性结果、精确文本比较结果及相关限制；比较基准是按所选清理规则得到的预期文本。
- 对图片、公式、批注、页眉页脚等复杂内容的提示。
- 官方水印检测状态 `not_tested`，不要把它理解成“未检出”。

验收步骤详见 [验证说明](验证说明.md)。即使正文一致性通过，也请手动查看输出文件；比较逻辑无法证明全部视觉元素一致。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `python` | 安装 Python 3.11+ 并添加到 PATH，重新打开终端 |
| 缺少依赖模块 | 在项目目录重新运行安装脚本，或执行 `python -m pip install -r requirements.txt` |
| 找不到 Tkinter | 使用包含 Tcl/Tk 的 Python 安装；也可以直接使用命令行 |
| 输出文件已存在 | 改用新的输出文件名；工具不会覆盖已有文件 |
| 输出文件夹不存在 | 先在文件管理器中创建文件夹，再选择输出路径 |
| 重建被复杂内容检查阻止 | 查看报告；需要保留内容时使用保留模式，接受丢失时才使用 `--allow-lossy` |
| 扫描 PDF 无法重建 | 本工具没有 OCR，请先用自己选定的 OCR 软件生成文本层，并自行校对 |
| `.doc` 不支持 | 在 Word 或兼容软件中先另存为 `.docx` |
| 加密、损坏或不受支持的文件报错 | 用能正常打开原件的软件另存一个有效副本，再运行检查 |
| 检测不到 GPT 水印 | 本工具没有官方检测能力；`not_tested` 是未测试，不是阴性结果 |
