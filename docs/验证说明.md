# 验证说明

## 结论边界

本项目可以提供“哪些指定字符或所检元数据发生了变化”“可抽取正文是否一致”的本地证据。它不能提供“OpenAI textGrain 已被去除”或“仍能被官方检测到”的实测结论。

目前没有接入官方 textGrain 检测器，也没有收到并完成真实用户文件的官方检测。官方检测状态为 `not_tested`；不得将其译为“未检出”“已通过”或“无水印”。具体原理及官方来源见 [技术原理与官方依据](技术原理与官方依据.md)。

## 每项证据说明什么

| 证据 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 处理前后指定字符计数 | 在本工具检查到的文本范围中，指定字符数量发生变化 | 所有隐藏内容均被清除、统计文本水印已去除 |
| 支持的元数据字段检查 | 所检字段已被清理或仍有残留 | 文件已被完全匿名化、所有嵌入信息已清除 |
| 输入输出文件摘要 | 报告对应哪些具体文件，文件字节是否改变 | 内容正确、没有水印 |
| 忽略空白的正文比较 | 输出抽取文字与预期文本去掉全部空白后是否相同 | 空格位置、分段、阅读顺序、排版完全相同 |
| 精确文本比较 | 输出抽取文字与预期文本是否逐字符相同 | 图片、公式、批注或页面渲染完全相同 |
| 合成样例运行记录 | 指定构造样例的本地检查结果可复现 | 真实 textGrain 样本去水印成功、所有文档均适用 |
| 自动化测试和覆盖率 | 受测试行为按断言运行，测试覆盖一定代码范围 | 每种实际文档都被测试、第三方检测器无法识别 |
| 官方检测 `not_tested` | 未执行官方检测 | 检测阴性或检测阳性 |

预期文本指原件抽取文字应用本次选定的清理规则后的结果；PDF 保留模式保持页面文字原样。并非把有意删除的字符作为意外损失，也不能据此把原件中未被抽取到的图片和公式算作已经核对。

## 复现合成样例

在项目根目录安装依赖后，执行：

```powershell
python -m pip install -r requirements.txt
python scripts/verify_evidence.py evidence/sample-run
python scripts/generate_evidence.py --output evidence/new-run
python scripts/verify_evidence.py evidence/new-run
```

`evidence/sample-run/` 是交付的合成样例。使用一个尚不存在的新目录保存每次重新生成的证据，避免混淆旧证据。生成脚本构造受控样例并生成处理及检查记录，实际产物以该次运行输出为准。所有构造样例都应明确标记为合成数据，不应被称为 GPT 官方水印样本。

`scripts/verify_evidence.py` 不调用 `cleanroom` 的扫描或清理函数，而是直接读取 DOCX 包内 XML 和 PDF 对象。它核对全部受查 `w:t` 节点（包括页眉）、指定字符数量、`docProps` 部件、ZWJ/ZWNJ 保留情况、所检 PDF 元数据及页面内容流的字节一致性。这提供了独立于清理函数的交叉检查，但仍然不是官方水印检测。

复核时保留同一组输入、输出、报告和运行日志。不要只截取“字符数量为零”的画面；完整报告中的检测范围、处理模式和 `not_tested` 状态同样属于证据。

## 用自己的文件验收

1. 保存原件，运行 `inspect`，记录工具检查到的字符、元数据及复杂内容。
2. 选择保留或重建模式，并使用新输出路径运行 `clean`。
3. 保存该次输出和审计报告，再对输出运行 `inspect`，交叉核对残留项目。
4. 检查忽略空白的正文比较和精确比较。出现不一致时，不应继续宣称“内容完全一样”。
5. 用 Word 或 PDF 阅读器打开新文件，人工检查文字、顺序、表格、图片、公式、脚注、页眉页脚与分页。
6. 将结论写成“通过了哪些本地检查，哪些项目仍有残留或未测试”。

审计报告文件名为完整输出文件名加 `.audit.json`，例如 `output.pdf.audit.json`。可定位这些字段：

| 字段 | 解释 |
| --- | --- |
| `before` / `after` | 输入输出文件摘要、文本及所检属性 |
| `options` / `operation` | 本次选择和实际处理方式 |
| `verification.expected_text_matches` | 去掉全部空白后的预期正文比较 |
| `verification.exact_extracted_text_matches` | 预期文本与输出抽取文字的精确比较 |
| `verification.selected_characters_remaining` | 输出抽取正文中的指定字符数量；另看 `after.extra_text_invisible_characters` 中的附加文本 |
| `verification.visual_layout` | `not_verified`，程序没有证明视觉版式一致 |
| `verification.statistical_watermark` / `verification.ai_detector` | `not_tested`，未测试对应检测器 |
| `openai_text_watermark.status` / `verdict` | `not_tested` / `unknown`，官方检测未执行，结论未知 |

PDF 保留模式不清理页面文字，所以出现指定字符残留并不一定代表程序失效。DOCX 保留模式也可能保留复杂部件中的信息。重建模式可能只保留可抽取正文，不能因其文件更干净便忽略内容损失。

## 自动化测试

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest --cov=cleanroom --cov-report=term-missing --cov-fail-under=80
```

使用当前运行的完整输出记录测试结果和覆盖率。不要将配置中的 `80` 阈值当作实际覆盖率；不要把本地某个 Python / 操作系统版本的结果描述成全部 GitHub Actions 矩阵均已通过。

GitHub Actions 配置会在 Windows 与 Ubuntu 的 Python 3.11、3.12、3.13 环境执行测试。Ubuntu 通过 Xvfb 虚拟显示运行包含图形界面的测试；本地无显示的 Linux 环境也需要相应依赖。上传后查看自己仓库的实际运行记录，失败时保留日志并处理。

## 关于真实 textGrain 检测

若未来获得有明确授权的官方检测渠道，需要另外记录检测器版本、输入样本、处理参数、检测条件和前后结果。本工具当前不提供该能力，也没有此类实测证据。

一般 AI 写作识别器的概率评分不能替代官方水印检测；概率变低不证明水印被去除。相同文本经过重打、复制或更换文件封装后，文件信息可能变化，而选词序列仍然相同。

建议使用的结论表述：

> 本次处理清理了审计报告所列的指定字符和支持的文档属性。正文及版式是否满足要求，见具体比较结果和人工核对记录。官方 textGrain 检测未执行，不能判断该水印是否存在或已被去除。
